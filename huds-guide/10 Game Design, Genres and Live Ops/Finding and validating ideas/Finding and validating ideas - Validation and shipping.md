# Finding and validating ideas - Validation and shipping

Up: [[Finding and validating ideas]] · Previous: [[Finding and validating ideas - Idea vetting checklist]]

- Build a minimum viable product (MVP) of just the core loop. Test with friends; continue only if it is fun.
- Ask friends for a score out of 10 before and after changes, and request brutal honesty.
- Playtest with young kids; if an 8-year-old cannot understand a rule, it is hidden (owner-recommended).
- Run community playtests and join voice chat with testers. Remember the game is multiplayer even when testing solo.
- Most recommend shipping an MVP with a good loop and polishing after traction. It still needs basic polish, progression and playtesting.
- A planning procedure that works:
    1. Study charts and the creator exchange for gaps.
    2. Spend a day planning, with three unbiased reasons it will work.
    3. Prototype with AI and test with friends.
    4. Build for a week, then make thumbnails emulating the inspirations.
    5. Release, add funnels and a feedback system, then start ads.
    6. Iterate for a week; drop it if stuck, and learn why.
- A good click-through rate (CTR), such as 7%, with very poor engagement means a fantasy mismatch.
- A struggling game has two options: add a big twist plus a reskin, or recycle its systems into the next game.
- If CCU is below about 60 and falling with no recovery, start another project (low confidence).
- First games are for learning: copy something simple, ship small, fail fast. Do not spend a year on a first project.
- A first game takes about a month if learning, a week if rushing. At "50% done" you are usually about 10% done.
- Bugs during an ad run can kill a game.
- Benchmarks are per genre, so changing genre changes your stats. Genre can change only once every 3 months.
- The maturity questionnaire can wrongly limit a game to 16+; one chase mechanic was rated as violence.
