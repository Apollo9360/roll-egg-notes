# Multiplayer and PvP

Up: [[Game Design, Genres and Live Ops]] · Previous: [[Polish, juice and visual style]] · Next: [[Updates and live ops (Game Design)]]

- Roblox is social, so make multiplayer games over single-player (owner-recommended).
- PvP games need AI bots to fill dead servers and teach first-time users (owner-recommended).
- Design for low CCU at launch. A game needing 50 per server fails when ads bring 9 CCU.
- Steal-type games break at 2–4 players per server; a lone player in a 2-player game bounces before anyone joins.
- Shared server-wide money fails with three or more players; loot gets taken instantly.
- At launch, run PvP within the server, not global queues. Off-platform matchmaking or MemoryStore queues need external services.
- Use the Roblox-optimized server size. Simulators commonly run 6–8 per server (low confidence).
- Social, round-based play with spectating while waiting cuts bounce rate.
- Add a light knockback shove so players can interact.
- New-player servers or a base lock help, but hidden rules (such as a 5–15 minute lock) confuse kids.
- In PvP games, social flex usually comes from cosmetics; skin economy and VFX matter a lot.
