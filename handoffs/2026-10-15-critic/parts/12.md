## 12. Trust and security (6/10)
The server owns money, Speed, egg size, placement and every daily or code claim. I found no dupe and no race in the money or claim paths. The weak spots are the ones the server never checks: where a player stands (client position), who gets a plot, and one-tap irreversible actions that hurt kids more than hackers do.

All claims below are [Static] (read from code) unless marked otherwise. No exploit was run and nothing was edited.

### The kid's experience
| Time | What happens | Risk |
|---|---|---|
| Join, server already has 5+ players | The 6th player never gets a plot (`PlotService.assign`, lines 212-226, only calls `warn`). They can still steal an egg, then every placement fails with no toast (`EggService.placeEgg`, lines 784-787, returns silently; `PenService.acceptDelivery`, lines 495-499, returns `false` with no reason). | Bounce on minute 3 |
| Minute 5, pet list | Pets are sorted best-first. "Place" and "Sell" sit on the same row. One tap on Sell removes the pet for good, with no confirm (`HudController` lines 399-424). | A kid sells their best pet by accident and quits |
| Minute 15, beyond the Meadow | An exploiter with teleport or speed grabs deep-zone eggs, or bats egg carriers, and the server never checks their movement. | Honest kids lose eggs and the leaderboard is polluted |
| Day 2 return | The 10-minute PvP shield counts wall-clock time, so it is already spent (`PvPService` lines 191-199). | Knocked loose beyond the Meadow with no shield |
| Day 7 | Daily, quest and code claims are atomic and use server UTC time. | None found |

### Problems, ranked
1. **Plot cap vs server cap: players 6+ can steal an egg but can never place it, and the game says nothing.** [Static] `Workspace.World.Plots` has 5 children (`MapLayout.PlotCount = 5`), while `Players.MaxPlayers = 60` as read in Studio. The live Creator Hub value was not readable. `EggService.placeEgg` returns with no notification when `PlotService.GetIndex` is nil, and `refreshIncubators` returns early at `PenService` line 147. Already known to the team as P0.1. I add the silent failure on top: the player is not stranded cleanly, they are walked into guards with an egg they can never deliver.
   - Fix: set max players to 5 now. Then either build 12 plots or make the server refuse a join with no free plot, with a `TeleportAsync` to a new server. Add a toast at `placeEgg`'s early return. Effort XS (setting) to M (more plots) · Impact Very high.
2. **Selling a pet is one tap, has no undo, and a fast double-tap can sell two.** [Static] `HudController` line 423 fires `RequestSellPet` at once. `PenService.sellPet` (lines 801-818) removes the pet, placed or not, with no lock. The list re-sorts by income and rebuilds (lines 399-401), so a second tap on the same spot lands on the next pet. The server gap between sells is 0.15 s (`PenService` line 880). [Computed] Sale value = 30 s of that pet's income (`Economy.SellFraction` 0.5 × 60 s, `Economy.lua` line 488), so the best pet is the one most likely lost, for almost nothing.
   - Fix: make the button two-step ("Tap again to sell", reverts after 2 s) and disable all Sell buttons for 0.8 s after any sale. Block selling placed pets and any pet worth more than 50% of the current best, unless held for 1 s. Effort XS · Impact High.
3. **Player position is fully client-authoritative: zone gates, guards and bat hits can all be bypassed.** [Static] The only movement check is `EggService.carryTick` (lines 846-855), and it only limits egg growth to expected walk speed (`MaxSampleSlack` 1.35). It does not stop the move. `RequiredSpeed` is "shown on the entrance sign (soft gate)" (`Biomes.lua` line 56). The server uses it only for Index caps and Huge-egg zone choice, never in `grabEgg`. The chase ends when the client's position passes the lock line (`GuardService` lines 453-456). `PvPService.canHit` (lines 317-346) trusts the attacker's `CFrame.LookVector` and position, and knockback and trap root are applied on the victim's own client (`PvPEvent` and `WalkSpeed`), which a modified client ignores. [Computed] A Speed-10 account teleporting to a Cosmic nest can deliver an egg whose Common (`AstroPup` BaseIncome 150,000) is about 9,400x an Owl (16, Meadow Epic), before size and mutation multipliers.
   - Fix: in `SpeedService.wheelTick` (0.25 s), store the last position per player. If the flat move exceeds `expected × 0.25 × 1.6 + 6` studs and the server did not cause it (knockback, trap, `TeleportHome`), snap the root back, add a strike, and kick at 6 strikes a minute. Refuse nest grabs, placements and bat swings for 3 s after a strike. Log accounts whose Money per minute passes a threshold. Effort M · Impact High.
4. **Hidden pet identity leaks through the egg timer.** [Static] `DataService.sanitize` (lines 137-148) strips `PetId` but still sends `Size` and `HatchSeconds`. `Curves.HatchSeconds = pet.HatchSeconds × HatchMultiplier(size)` (`Curves` lines 102-108 and 1853-1854), and both inputs ship to the client. Per-pet base times in a zone are all different, for example Meadow 3, 10, 20, 35, 60, 120 s and Secret Eggbert 180 s (`Pets` config lines 57-62, 105). The pet is rolled at placement (`acceptDelivery` lines 519-521), so a kid or modded client knows "this egg is the Legendary" the moment it lands, before the reveal. [Opinion] That takes the surprise out of the game's main payoff and tells people which eggs are worth a Robux Skip.
   - Fix: make hatch time depend on rarity band plus ±15% random per-egg jitter, not on species. Or accept it and make it a feature ("timer glow = rarity"). Effort S · Impact Medium.
5. **Newbie shield runs on the real clock, not play time.** [Static] `ProtectedUntil = firstLoad + 600` (`PvPService` lines 63, 194-199), and `IsProtected` is `os.time() < ProtectedUntil or Index empty` (line 191). The 600 s keep running while the kid is offline. A kid who plays 4 minutes and returns tomorrow has no shield. The Meadow is a safe biome (line 62, `inFightZone` lines 143-149), so the risk starts at the Riverbank gate (`RequiredSpeed` 300, `Biomes.lua` line 97).
   - Fix: store `ProtectedLeft` seconds in data and decrement it online in the 1 Hz `protectionTick`. Effort S · Impact Medium.
6. **Paying customers can silently lose a pass for the whole session.** [Static] `MonetizationService.loadPasses` (lines 469-481) calls `UserOwnsGamePassAsync` once per join. If a call fails it only `warn`s, with no retry and no message. Pass2xMoney (399 R$) or Pass2xGrowth (467 R$) then does nothing until the next join. Related: `grantHatch` (lines 326-329) takes the Robux and gives no credit if the egg finished before the receipt arrived. `Traps5` is still `Id = 0`, so it shows "Coming soon!" on live servers (lines 544-548).
   - Fix: retry 3 times (2, 4, 8 s) and re-check every 5 minutes until one succeeds. Show "Checking your pass..." while it runs. For the hatch edge, refund as a banked credit. Effort XS · Impact Medium (High for spenders).
7. **A "secured" egg stays free forever, even after it returns to a nest.** [Static] `returnToNest` (lines 335-354) keeps `Size` and `Secured`. `Drop` and the 60 s ground expiry (lines 728-733) do the same. `GuardService` lines 570-573 skip waking the guard for secured eggs, and lines 397-399 let a second thief "get away clean". A friend (or a disconnect) can leave a pre-grown, guard-immune egg in a nest for anyone to take.
   - Fix: in `returnToNest`, set `Secured = nil` and reset `Size` to `StartSize`. Effort XS · Impact Low-Medium.
8. **Daily refill and Night Run start orphan carried eggs, so a later drop deletes them.** [Static] `refillNests` (lines 313-328) destroys the registry entry of whatever sits in each nest slot. A carried egg still holds its slot, so it is destroyed too. `EventService` line 96 calls `RefillNests("NightRun")` mid-day. When that player later drops or is batted, `Drop` (lines 700-717) loops on `eggs[egg.Id]`, which is nil. The egg is never grabbable and its part stays in the world. Catches inside the biome already drop it quietly (`returnToNest`, lines 340-346).
   - Fix: in `refillNests`, detach a carried egg (`NestIndex = nil`) instead of destroying it, and re-register `eggs[egg.Id]` in `Drop`. Effort XS · Impact Low-Medium (peaks on the Night Run).
9. **First-walk Speed can be re-farmed by rejoining.** [Static] `FirstWalkService.collected` is memory only (line 75) and the gate is `TutorialStep == 1` (line 47). [Computed] 13 pickups × 2 = +26 Speed per join until the first egg is grabbed. About 12 rejoins reach the Riverbank gate of 300. It is harmless for most kids and small, but it is a free dupe.
   - Fix: persist a bitmask in `data.FirstWalk`. Effort XS · Impact Low.
10. **Offline pay can be paid twice after an unclean shutdown, and unreleased codes are readable.** [Static] `grantOffline` (`EconomyService` lines 70-81) pays up to 8 h × 50% (`Economy.lua` lines 489-490) but never updates `LastSeen`, which is only written on a clean leave (`DataService` line 209). A crash after autosave pays the same window again. [Static] `Codes.List` (`Codes.lua` lines 892-896) is in ReplicatedStorage, so any future code is readable by a modded client before launch.
   - Fix: set `data.LastSeen = os.time()` right after paying and every 60 s. Move codes to `ServerStorage` or a server-only module. Effort XS · Impact Low.

### What's good
Every economy remote validates on the server: `RequestBuy` must equal the next tier and goes through the atomic `DataService.Spend` (`DataService` lines 253-260). Daily, quest and code claims set their flag before paying, never yield, and use server UTC time (`RetentionService` lines 143-165, 247-267, 304-330), so there is no claim race and no clock cheat. Egg size is only ever written by the server (`EggService.carryTick`), placement needs plot, reach and spacing checks (`EggService` lines 781-798, `PenService.checkSpot`), and picked-up eggs re-seat without firing `Delivered`, so quests cannot be farmed (lines 800-816). Robux receipts are idempotent per `PurchaseId` and only marked after a successful grant (`MonetizationService._decide`, lines 401-423). The admin check is server-side, the Studio-only free grants are closed on live servers, and every remote I read has a rate limit or a state gate.

### Top 3 for the summary
1. Set the server cap to the plot count (5) and show a toast when placement has no plot (`PlotService.assign`, `EggService.placeEgg`).
2. Add a two-tap sell confirm with a short lockout and protect the top pets (`HudController` lines 419-424).
3. Add a server movement check in `SpeedService.wheelTick` that snaps back illegal jumps and blocks grabs, placements and bat hits after one.
